# CLAUDE.md — paroxysm permanent project instructions

Read this first in every conversation. It holds standing rules, not history. Current progress is in `PROJECT_STATUS.md`; the original research is in `RESEARCH_AND_ARCHITECTURE.md`. The project files in the folder are the source of truth for code.

## 1. What paroxysm is

paroxysm is a static web proxy built by transforming the abandoned **mirage** project. The goal is a proxy that a user launches by downloading and opening a **single `index.svg`** through `file://` in Chrome. The SVG bootstraps everything else; the supporting runtime files are static assets distributed through GitHub and jsDelivr.

- The final user-facing deliverable is one file named `index.svg`. Supporting files are not embedded in it.
- Keep the project static. No backend of our own, no build system, no package manager, no unnecessary dependencies. The only unavoidable backend is a WISP server (third-party endpoints, listed in `paroxysm.config.js`).
- Do not create a separate, independently designed or hosted proxy website. The HTTPS-hosted copy is part of paroxysm's own distribution.
- Per-file SHA-256 hashing (M6) and ECDSA P-256 manifest signing (M9, 2026-11-23) are both built. The private signing key lives only on the user's machine (`%USERPROFILE%\.paroxysm\signing-key.json`); never read it into the repository, docs or chat.

## 2. Naming

`mirage` and `paroxysm` are always lowercase, everywhere: UI text, file names, docs, branding, comments, even at the start of a sentence. Use `paroxysm://` for internal pages. Other names keep their normal case (Fern, Scramjet, Epoxy, WISP, Three.js).

## 3. The protected proxy engine (do not touch)

mirage's proxy implementation is protected. Inspect it freely; do not rebuild, replace, rewrite or modify it.

**Protected files (checked by hash against `protected.sha256`; `sw.js` and `controller/controller.sw.js` are still mirage's own, the rest of `scramjet/`, `controller/` and `epoxy/` were replaced as one approved set on 2026-11-22, see the versions below):** `scramjet/scramjet.js`, `scramjet/scramjet.wasm`, `controller/*` (`controller.api.js`, `controller.sw.js`, `controller.inject.js`, `controller-external.mjs`, source maps), `epoxy/index.js`, `sw.js`.

- Run `python verify_protected.py` (uses `protected.sha256`) before and after any change, and after handing files over. It must print `ALL PROTECTED FILES UNCHANGED`.
- **Protected logic inside `index.html`'s script:** `probeWisp`, the `EpoxyTransport` and `Controller` construction, `controller.wait()`, `createFrame`, `frame.go`, the service worker wait, the `register("/sw.js")` bootstrap block, and `init()` itself. These were verified identical to mirage except for two cosmetic edits inside `init()`: the log tags (`[mirage]` renamed `[paroxysm]`) and the internal-page check (`"mirage://"` replaced by the `LOCAL_SCHEME` constant, i.e. `paroxysm://`).
- The one approved behaviour change near the engine: the wisp endpoint is now chosen by an ordered-fallback wrapper placed **around** `init()` (`findWispServer`, the `init = async function` wrapper). The probing, transport and controller logic of `init()` is unchanged.
- **M5 adapter (2026-11-23, approved, engine files untouched):** `paroxysm-adapter.js` (loaded right after `controller.api.js`) sets `$scramjetController.config.{prefix, scramjetPath, injectPath, wasmPath}` to the folder the page is served from and wraps `navigator.serviceWorker.register` so mirage's `register("/sw.js")` registers `<folder>paroxysm-sw.js` (scope `<folder>`); `paroxysm-sw.js` is `importScripts("controller/controller.sw.js", "sw-glue.js")` and `sw-glue.js` is mirage's fetch glue without `importScripts`. It applies everywhere, also at the root (the user chose "always"), so `sw.js` stays protected but is no longer registered. **Since M6 (2026-11-23)** the shim registers `<folder>loader-sw.js` instead (section 4 item 3; `paroxysm-sw.js`, M5's plain worker, was deleted after the user confirmed M6), with a dev mode (`loader-sw.js?dev=1`, files straight from the server without hash checks) only on localhost and only when the address has `?dev` or the page carries Live Server's injected `<!-- Code injected by live-server -->` comment (Live Server changes every HTML file, so no hash can match).
- **Approved adapters around the engine (2026-11-22, engine files untouched):** `paroxysm-transport.js` wraps `EpoxyTransport.prototype.request` and `connect` from outside (loaded after `epoxy/index.js`); when a request fails with `Wisp(MuxTaskEnded)` it probes the wisp URL, calls the transport's own `init()` for a new client and retries (shared reconnect, about 30 s, temporary pill via `window.paroxysmPill`). In `index.html` (outside the protected logic) a `$controller$swrevive` listener re-sends the controller's port when the controller itself ignored the announcement (its first 5 s) and reloads proxied frames that loaded as the static server's 404 while the restarted worker had no route (detected by the missing `$scramjet` global; at most 2 reloads, within 20 s of the revive). **Extended 2026-11-22 (B16):** a proxied HTML frame without `$scramjet` is also retried when no revive message arrived (its controller re-sends its port, then the frame reloads; 2 tries per 20 s per tab), and a shell the worker does not control (after a hard reload) reloads itself once, with a pill if it stays uncontrolled.
- Use external adapters or compatibility layers. If integration seems to require changing the engine, **stop, explain why, and wait for explicit approval** before editing anything.
- Versions are coupled. The engine is now **Scramjet 2.1.0** (`@mercuryworkshop/scramjet`, GitHub release v2.1.0, commit `2b2adc6`), **controller 0.1.0** (`@mercuryworkshop/scramjet-controller` from npm, built from the same commit) and **Epoxy transport 3.0.2** (`@mercuryworkshop/epoxy-transport`, `dist/index.js`, epoxy-tls 2.1.20-1); `sw.js` and `controller.sw.js` are unchanged from mirage. Since controller 0.1.0 a release build accepts any Scramjet with the same major.minor (2.1.x); prerelease builds must match exactly. The controller has no `VERSION` export any more: use `$scramjetController.versionInfo.version`. Replace `scramjet/`, `controller/` (and possibly `epoxy/`) only as one set, only with approval, and re-run the baseline checklist. Take the controller from npm or a tagged release, not from the moving "Continuous Build" pre-release. Do not mix with Fern's alpha.2 files. Upgrade done 2026-11-22; the user re-ran the baseline checklist on it (B10, YouTube pages, fails with an Epoxy HTTP/2 error: a known transport limit, see `PROJECT_STATUS.md`).

## 4. Target architecture (Fern-inspired)

Reproduce Fern's technique (github.com/frnlol/frn, built output only, no license file). **Write the loader independently from the documented behaviour; do not copy Fern's minified code.** Do not replicate Fern's obfuscation or its ad-script loader (`aclib.runPop`).

**Built in M7 (2026-11-23):** `index.svg` (both roles in one file; since M8 `HOMES` is `@main` and files come from the release commit in `m.json`), `paroxysm-outer.js`, and loader progress messages; items 1, 2 and 6 below. AI keys and the Puter token stay in `localStorage` with a warning in Settings > AI (user decision a, 2026-11-23).

1. **Local `index.svg` (file://)** is the outer document and stays visible in the address bar. It detects that a Service Worker can't register on `file://` (verified: `navigator.serviceWorker` exists but `register()` fails with an opaque-origin error).
2. It races its HTTPS mirrors and **embeds the winner in an iframe**. The inner HTTPS document has its own origin and registers the real Service Worker. A **full-page redirect is only the fallback** when the iframe cannot start its Service Worker (Fern's `nosw` message to the parent, then redirect with `?ld=0`) or when the browser has no service workers at all. Never simplify this into an ordinary redirect.
3. The registered worker (`loader-sw.js`, our own) is a loader/package manager: it fetches a manifest (`m.json`, SHA-256 per file, signature later), downloads and verifies files, and **virtualizes** the app worker: it temporarily replaces `self.addEventListener` to capture handlers, evaluates the app worker source with `new Function(...)`, then dispatches `fetch`, `message` (ports preserved), `push` and `notificationclick` to the captured handlers using synthetic events. Captured `install`/`activate` handlers are not dispatched.
4. The app worker for paroxysm = `controller/controller.sw.js` followed by `sw-glue.js` (mirage's five-line fetch glue without `importScripts`), evaluated in **one function body** so `$scramjetController` is visible. `importScripts` after install is blocked (verified), so no `importScripts`.
5. A page adapter (`paroxysm-adapter.js`, loaded before the inline script; built in M5) sets `$scramjetController.config.{prefix, scramjetPath, injectPath, wasmPath}` to scope-relative values and wraps `navigator.serviceWorker.register` so `register("/sw.js")` registers the loader. This is approval item A3 and belongs to the SVG phase.
6. After the worker takes over it serves the app as `text/html`, so the UI stays plain HTML (verified: a worker can answer in-scope navigations with synthesized `text/html` on jsDelivr).
7. WISP is the proxy transport (`wss://`). A WISP-over-HTTP mirror fallback like Fern's is optional and belongs to hardening.

Verified platform facts: jsDelivr serves SVG as `image/svg+xml` with no CSP (scripts run); `@main` URLs are cached 7 days in browsers and 12 hours on the CDN, so pin app files to a commit; a worker registers at a `/gh/<owner>/<repo>@<ref>/` scope with no extra headers; `new Function()` is allowed in a jsDelivr-served worker; raw.githubusercontent.com sends a sandbox CSP and cannot be an app origin; everything on `cdn.jsdelivr.net` shares one origin (never enumerate or unregister other registrations; namespace storage). Verified in M4 (2026-11-23, headless Chrome for Testing 158 and the user's Chrome 156): a `file://` page can embed a jsDelivr page in an iframe (no frame-blocking headers); the worker registers and controls pages inside it and survives restarts; its storage and registration persist but are partitioned under the `file://` top site (shared by every local file, invisible to top-level jsDelivr pages, different from the `?ld=0` fallback's storage); the iframe needs the `allow` list for fullscreen, autoplay, clipboard, camera and microphone; messages from the `file://` parent arrive with origin `"null"`, so check `event.source`.

## 5. UI conventions and branding

- Dark by default, with a Light theme (Settings > Appearance, `data-theme` on `<html>`). Every surface is the accent mixed into black (dark) or white (light) with `color-mix` (dark: `--bg` 4.5%, `--surface` 7.5%, `--surface-2` 12%, `--surface-3` 17%, matched to Fern's sampled pixels), so the UI follows the accent. Text and icon colours are also lightly tinted by the accent (`--text`, `--text-2`, `--text-3`; icons use `currentColor`); generous padding on a 4 px scale; consistent type and components; minimal, modern, no clutter; no unnecessary redesign of working functionality.
- Typeface: **Inter** (variable, bundled in `fonts/`: `inter-latin-wght-normal.woff2` plus the cyrillic, cyrillic-ext and greek subsets, each with its `unicode-range` in `paroxysm.css`; the project moved from Inter Tight in round 3); wordmark weight 600 (SemiBold).
- The main accent is `#ae72df`, named **Paroxysm** (the default and the first swatch). Accents have one-word names (Glacier, Sunset, ...; list in `paroxysm-settings.js`). Text on the accent is black or white by WCAG contrast. In the **browser shell**, a selected tab is **solid accent fill with no outline**, and hovering an inactive tab or sidebar link shows the accent at about 16% opacity. Rail tabs, rail links, settings nav items, choices, rows, the omnibox, search bars and buttons are **fully rounded**; the page area is 14 px and settings cards 20 px; the search button is a circle. Tab labels are weight 500.
- Top bar (46 px; the omnibox and buttons keep their 30 px and 28 px heights): the **paroxysm icon** at the far left (dark-mode or light-mode icon file by theme, not tinted by the accent; click opens Home), then collapse (sidebar layout only), back, forward (both grey out when the active frame has no page to go to), reload; a centred omnibox with a bookmark button inside it; on the right the New tab button (horizontal layout only), a layout button and the menu button, whose dropdown (`.menu`, built in `index.html` by `openMenu`) has six groups separated by lines, in this order: (1) pages: New tab, Games, AI, Settings; (2) connection: a status line with the current wisp server and whether it answers a probe (not a permanent dot: it only exists while the menu is open), Reconnect (`EpoxyTransport.reconnect` from `paroxysm-transport.js`), Find best server; (3) quick toggles: light/dark theme, show/hide bookmarks bar (setting `bookmarksBar`), sidebar/horizontal tabs; (4) cloaking: tab disguise on/off (setting `tabCloakLast` remembers the preset, default Google Docs) and Panic now; (5) clear data, each behind a confirmation: bookmarks, game saves (`paroxysm:game-saves`, favorites and recents are kept), proxy cookies (controller cookie jar); (6) About (opens Settings > About) with the version and the engine versions.
